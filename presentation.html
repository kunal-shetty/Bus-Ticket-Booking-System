02 — Introduction

Why This Project?

!
Problem Statement

Conventional bus ticketing across India relies on manual counter-based systems that create major operational issues:

  • Double Bookings — Same seat sold to multiple passengers without real-time tracking.
  • No Visibility — Passengers can't check seat availability before visiting the counter.
  • Paper Records — Handwritten logs are fragile and impossible to audit efficiently.
  • Slow Processing — Each booking takes minutes of manual entry, creating long queues.
✦
Our Solution

A complete digital platform that eliminates every pain point of the manual process:

  • Instant Authentication — Secure login and registration via MySQL database.
  • Visual Seat Map — Realistic 2+2 bus layout showing availability at a glance.
  • Multi-Seat Booking — Select multiple seats in one atomic transaction.
  • Persistent History — Every booking is permanently stored and retrievable.

05 — Modules

MVC Implementation

Clean separation of concerns across five distinct layers

View Layer (FXML + CSS)
7 FXML screens define the UI declaratively. style.css applies the dark theme with indigo accents. Zero business logic in this layer — purely layout and styling.
Controller Layer
Each screen has a dedicated controller handling button clicks, form submissions, and navigation. Controllers call Services — never DAOs directly — maintaining clean dependencies.
Service Layer
AuthService handles login/register, BookingService manages atomic multi-seat booking, SessionService maintains global user state across screens.
DAO + Model Layer
Data Access Objects encapsulate raw SQL with PreparedStatement. Models (User, Bus, Seat, Booking) are POJOs carrying data between layers.

07 — Database

Schema Design

Normalized to 3NF with foreign key constraints and cascade rules

⬡ users
PK user_id (INT AUTO_INCREMENT)
name (VARCHAR) · email (VARCHAR, UNIQUE)
password (VARCHAR)
⬡ buses
PK bus_id (INT AUTO_INCREMENT)
bus_number (VARCHAR) · source (VARCHAR)
destination (VARCHAR) · total_seats (INT)
⬡ seats
PK seat_id (INT AUTO_INCREMENT)
FK bus_id → buses(bus_id) CASCADE
seat_number (INT) · is_booked (BOOLEAN)
⬡ bookings
PK booking_id (INT AUTO_INCREMENT)
FK user_id → users(user_id) CASCADE
FK bus_id → buses(bus_id) CASCADE
seat_number (INT) · booking_date (DATE)

All foreign keys use ON DELETE CASCADE for referential integrity
